## What Works

[2026-07-07] Pre-push CLI (`devdigest review --mode working`) reuses the review engine from a NEW entry point WITHOUT a PR. The reuse point is `reviewPullRequest` (@devdigest/reviewer-core) — the same pure engine `run-executor.runOneAgent` calls. New `ReviewService.reviewDiff(workspaceId, diff, opts)` (service.ts) mirrors `runOneAgent`'s engine call (resolve llm → load agent's enabled skills → `reviewPullRequest` → grounding) but deliberately drops ALL I/O: no persistence (no PR row), no repo-intel enrichment (working copy isn't an indexed repo → prompt = repo-intel-off baseline). Per-agent try/catch isolates failures into a result `error` field. This is the clean pattern for any "review a raw diff" surface — do NOT fake a PR row to go through `runReviewAndWait`.

[2026-07-06] Blast Radius (L04) was ~80% reuse, not new code. `repoIntel.getBlastRadius(repoId, changedFiles)` (repo-intel/service.ts:220) ALREADY returns the full map (changedSymbols + callers{file,symbol,viaSymbol,line,rank} + impactedEndpoints + factsByFile + degraded), and the shared `BlastRadius` contract (vendor/shared/contracts/brief.ts) ALREADY models changed_symbols→downstream[{symbol,callers,endpoints_affected,crons_affected}]→summary. Net-new work was only: a thin `modules/blast/` (pure `composeBlastRadius` + service + `GET /pulls/:id/blast`) and one facade read for 2-level reachability. Before building an L0x feature, check the facade + `brief.ts` — the contract and most logic are usually pre-scaffolded.

[2026-07-06] MCP handlers are pure `(container, input) => CallToolResult` functions exported from `server/src/mcp/tools/*.ts`, with the SDK wiring (`server.registerTool`) isolated in `register.ts`. This makes every handler testable WITHOUT spawning `StdioServerTransport` — integration tests call the handler directly with a real-PG `Container`. Same for the conventions Resource: its `list`/`read` bodies are extracted into exported `listConventionResources`/`readConventions` so they test without an `McpServer`.

[2026-07-06] MCP integration tests can't use `buildMcpContainer()` — it reads the DB URL from `loadConfig().databaseUrl` (env), so it won't hit the dynamic testcontainer URL (`startPg` does NOT set `process.env.DATABASE_URL`). Build the Container directly instead: `new Container(config(), pg.handle.db, { llm: { openai, anthropic, openrouter } })` — exactly what `buildApp({ db })` does internally. `buildMcpContainer` is only for the real `pnpm mcp` process.

[2026-07-06] Blocking review path for MCP: added `ReviewService.runReviewAndWait()` alongside the fire-and-forget `runReview()`. Both share a private `queueRuns()` (creates the `agent_runs` rows up front); `runReviewAndWait` `await`s `executor.executeRuns` instead of `void`-ing it. Tests of the blocking path need NO `waitForPrRuns` polling — reviews are persisted by the time it returns. `run_agent_on_pr` uses it to return "a completed result, not an operation".

[2026-07-04] Proving "this route makes NO LLM call" in a test: build the app with `buildApp({ config, db })` and NO `overrides` at all (no llm/embedder/git mocks). `container.llm(id)` is a lazy async accessor, never eagerly constructed, so a route that never calls it works fully unmocked — and the test failing the moment someone adds a provider call is the guarantee. Used in `server/test/smart-diff.it.test.ts`.

[2026-07-04] Lesson verify gates (`scripts/verify-l03.sh`): run `check-vendor-sync.sh` in TWO passes — a full report that is non-fatal (it trips on pre-existing drift in `adapters.ts`/`knowledge.ts`/`productionize.ts`/`trace.ts`), then a SCOPED, fatal `diff` on only the contracts the lesson touches (`brief.ts`, `review-api.ts`, `platform.ts`). [2026-07-04] Counterfactual "token savings" logging: diff `container.tokenizer.count` between two prompt variants (header-only file list vs the full `diff.raw`), add the delta to the real `tokensIn`, then run `container.priceBook.estimate(model, …)` on both figures. ## Codebase Patterns

[2026-07-09] The `brief` module (SPEC-04) reaches `ReviewRepository` two DIFFERENT ways within one feature: `service.ts` does `new ReviewRepository(container.db)` (matching the `blast`/`onboarding`/`reviews` "local `this.repo`" convention) while its sibling `assembler.ts` uses the `container.reviewRepo` getter. Consequence: a test that swaps `container.reviewRepo` via `ContainerOverrides` reaches the assembler's reads but NOT the service's own `getPull`/`getBrief`/`upsertBrief`. Not a bug today (both wrap the same `container.db`; brief `.it.test.ts` only overrides `llm`), but pick ONE path per module if you want a single override-able instance. Flagged by architecture review, non-blocking — nuances the existing "reviews is the local-`this.repo` exception" note.

[2026-07-07] `parseUnifiedDiff` (adapters/git/diff-parser.ts) works DIRECTLY on real `git diff` output — the extra `index …`, `new file mode`, `deleted file`, `rename` header lines never match a branch and are skipped until a `@@` hunk starts. Caveat: a DELETED file has `+++ /dev/null` → its `path` stays `''` → it's dropped by the final `files.filter((f) => f.path)`. Fine for review (grounding needs new-side lines anyway), but don't expect deletions in the parsed `UnifiedDiff`. Working-tree diffs: `git diff HEAD` (mode `working`) captures staged+unstaged tracked changes but NOT untracked files.

[2026-07-06] `tryPersistentBlast` (repo-intel/service.ts:315) serves the index ONLY when `repo_index_state.status` is `'full'` or `'partial'`; anything else (or no row) falls through to the ripgrep path, which needs `repos.clone_path` — null in seed data → empty degraded result. To make blast return data from Postgres alone (tests/demo), seed `repo_index_state` with `status:'full'`.

[2026-07-06] Blast's 2-level "reachable endpoints" (facade `getReachableEndpoints`, repo-intel/service.ts) walks the REVERSE import graph: `file_edges` stores `fromFile imports toFile`, so "who depends on the changed files" = BFS over the `(repoId, toFile)` reverse index (`file_edges_repo_to_idx`), then union `file_facts.endpoints` of every visited file. Do NOT reuse `getCriticalPaths`' adjacency — that walks importer→imported (the wrong direction for blast).

[2026-07-04] `ReviewService` is the ONE module that does NOT use the `container.<x>Repo` lazy-getter DI pattern — it constructs `new ReviewRepository(container.db)` directly in its constructor and exposes it as `this.repo`. New methods on `ReviewService` (e.g. `smartDiffForPull`) must follow the local `this.repo` pattern, NOT introduce a container getter, to stay consistent within the module. (Nuances the general DI insight above — that rule holds for new modules; reviews is the established exception.)

[2026-07-04] The `SmartDiff` contract family (`SmartDiffRole`/`SmartDiffFile`/`SmartDiffGroup`/`SmartDiff` in `brief.ts:81-113`, aliased `SmartDiffResponse` in `review-api.ts`) was pre-scaffolded before any implementation — same as `Intent`. When a lesson names a contract "in vendor/shared", check it already exists before defining one. Smart Diff is a deterministic composer (`smart-diff.ts` `composeSmartDiff`) over `getPrFiles` + latest-review `findings` — zero LLM. `pseudocode_summary` on `SmartDiffFile` stays null in the no-LLM build (rendering it would require a model call).

[2026-06-26] `RunSummary` is defined in `vendor/shared/contracts/trace.ts`, NOT in `review-api.ts`. When adding fields to run data, update `trace.ts`, not `review-api.ts`.

[2026-06-26] `vendor/shared/` is a local copy shared between server and client — `server/src/vendor/shared/` and `client/src/vendor/shared/` must always be updated in sync. There is no npm package; files are edited in-place.

[2026-06-26] `agentRuns.prId` is nullable in the Drizzle schema even though a run always has a PR. Always null-guard before using it as a Map key: `if (r.prId && !map.has(r.prId))`.

[2026-06-26] `container.priceBook` is a lazy singleton on the Container class (`platform/container.ts:140`). `PriceBook.estimate(model, tokensIn, tokensOut)` is synchronous — safe to call in map/reduce without await.

[2026-06-28] Adding a new server module requires exactly 2 steps: create `modules/<name>/routes.ts` (default Fastify plugin export), then add one import + one entry in `modules/index.ts`. No filesystem autoload — static imports are required for tsx/vitest portability (documented in `modules/index.ts` comment). Do not use dynamic `import()` here.

[2026-06-28] Skills `source` field (`manual | imported_url | extracted | community`) is immutable after creation — `UpdateSkillBody` intentionally omits it. Set it once at creation via `CreateSkillBody`. If you add source to the update schema, the contract becomes ambiguous for version history.

[2026-06-28] Skills version bump rule differs from agents: only `body` changes increment the version. Name/description/type/enabled changes are in-place with no snapshot. The rule lives in `modules/skills/helpers.ts:isBodyChange` — change it there if the policy changes.

[2026-07-14] `AgentsService.restoreVersion` (SPEC-05's "Promote" mechanism, mirrors `SkillsService.restore`) must restore SKILL LINKS too, not just scalar config fields — `agent_versions.configJson.skills` snapshots the ordered skill ids linked at that version (see `AgentsRepository.snapshotVersion`), so a restore that only patches provider/model/system_prompt/etc. via `update()` would leave the agent's `agent_skills` links stale/inconsistent with the promoted config. Fix: after `this.update(...)`, also call `this.repo.setSkills(agentId, config.skills)`. `SkillsService.restore` doesn't have this problem because a skill VERSION only ever snapshots `body` (a single field), not a set of relations.

[2026-07-14] SPEC-05's precision formula (AC-9) is FINDING-level, not case-level, and this matters for noise attribution: a produced finding counts as "noise" if it overlaps ANY of the batch's `must_not_flag` cases' forbidden ranges — INCLUDING a finding produced during a DIFFERENT case's own execution (e.g. a `must_find` case's run that also hallucinates something landing in another case's forbidden zone). The denominator is ALL findings produced across the whole batch (every case's execution pooled together), not per-case. Implemented in `modules/evals/scoring.ts#computePrecision` by flattening `cases.flatMap(c => c.producedFindings)` before checking noise, rather than checking noise per-case. Get this wrong (scope noise-checking to only the SAME case) and precision silently over-reports.

[2026-07-09] Manual API testing needs NO auth header: `getContext()` → `LocalNoAuthProvider` always resolves the default workspace + system user, so a plain `curl http://localhost:3001/pulls/:id/brief` (no headers) hits the real tenant path. [2026-07-07] Running a TS bin outside `server/`: the `devdigest` bin (`server/bin/devdigest.mjs`) launches `node <tsx/dist/cli.mjs> <entry.ts>` and MUST set `TSX_TSCONFIG_PATH=<serverRoot>/tsconfig.json` in the child env — otherwise tsx resolves tsconfig from the CALLER's cwd (the user's repo), the `@devdigest/*` path aliases aren't found, and it dies with `ERR_MODULE_NOT_FOUND: Cannot find package '@devdigest/reviewer-core'`. Crucially, do NOT change the child's cwd to fix this — the CLI runs `git diff` in the caller's cwd on purpose (reviewing the developer's working copy). Keep cwd, redirect only the tsconfig. (`pnpm mcp` avoids this because `--dir server` sets cwd=server.)

[2026-07-06] `@modelcontextprotocol/sdk@1.29.0` has NO `package.json#exports` entry for `./server/mcp` or `./server/stdio`; the deep specifiers `@modelcontextprotocol/sdk/server/mcp.js` and `.../server/stdio.js` resolve only via the catch-all `"./*"` wildcard (→ `dist/esm/*`). [2026-07-06] `AuthProvider.currentWorkspace(req: unknown)` (vendor/shared/adapters.ts) takes a REQUIRED arg even though `LocalNoAuthProvider` ignores it. The request-less MCP process has no `FastifyRequest`; pass `undefined` — wrapped in `mcp/context.ts#currentWorkspace(container)` which documents the `getContext()` bypass. Every MCP handler/resource must call it to stay workspace-scoped.

[2026-07-06] Register `get_findings` with the RAW input shape (`GetFindingsInputShape`), NOT the `.refine()`'d `GetFindingsInput`. The SDK runs a full-schema refine at the transport layer and rejects with a protocol-level error; re-checking the run_id-XOR-(repo+pr) rule inside the handler instead lets it surface as a structured `VALIDATION_ERROR` (`{code,message,retry}`) an LLM can act on.

[2026-07-06] `LocalNoAuthProvider` (`adapters/auth/local.ts:28`) caches the resolved workspace in `this.cachedWorkspace` for the ENTIRE process lifetime (resolved by NAME `'default'`, not a persisted id). Consequence for the long-lived `pnpm mcp` stdio process: after a `docker compose down -v` + re-seed (which mints a new workspace UUID), the running MCP process keeps serving the old, now-deleted UUID → every tool returns empty (`list_agents` → 0) or `REPO_NOT_FOUND`. A `/mcp` reconnect/disable+enable inside a Claude Code session did NOT re-spawn the OS subprocess in practice — only a full client restart (`/exit` → `claude`) forces a fresh process + DB pool. ## Recurring Errors & Fixes

[2026-07-14] A scoped vendor-sync check built with `sed -n "/START/,/END/p"` breaks silently ("unknown command") when the marker strings themselves contain `/` characters — e.g. a comment-style bracket like `// --- EvalExpectation (SPEC-05) ---` collides with sed's own `/pattern/` address delimiter. Fix: extract the bracketed block with `awk -v start=... -v end=... '$0==start{capture=1} capture{print} $0==end{capture=0}'` — exact LINE EQUALITY, not regex, so no character in the marker text needs escaping. Used in `scripts/verify-l06.sh`'s scoped `EvalExpectation` block check (mirrors `verify-l03.sh`'s scoped-file pattern, but this one is scoped BELOW file granularity since `eval-ci.ts` itself has pre-existing unrelated drift). Verified both directions: a real drift (tampering the client copy's comment text) is correctly caught, and the untampered state passes.

[2026-07-14] `DiffHunk` (`vendor/shared/adapters.ts`) carries ONLY `newLineNumbers: number[]` (line numbers, for the citation-grounding gate) — never the actual line TEXT. This means a "freeze this diff" helper CANNOT reconstruct real diff content from an already-parsed `UnifiedDiff.files[].hunks[]` structure; doing so would only be able to synthesize placeholder text, silently breaking downstream LLM review quality (the reviewer would see fake content, not real code). The correct freeze source is `UnifiedDiff.raw` — `parseUnifiedDiff` already preserves the original raw text on the object it returns (`{ raw, files }`), and `reviewer-core/src/review/reduce.ts`'s `sliceDiff` independently confirms `.raw` is the sole carrier of diff body text (used for map-reduce chunking). `server/src/modules/evals/diff-freeze.ts#serializeUnifiedDiff` is therefore just `(diff) => diff.raw`, not a hunk-by-hunk re-emitter. If a future feature's plan asks for "reconstruct diff text from parsed hunks," check this insight first — it usually means "just use `.raw`."

[2026-07-14] Manually constructing an `eval_cases.input_diff` (or any ad-hoc unified-diff fixture) directly as a hunk-only string (`@@ -1,15 +1,15 @@\n...`) without the `diff --git a/<path> b/<path>` / `--- a/<path>` / `+++ b/<path>` header lines parses to `files: []` in `parseUnifiedDiff` — the parser only ever assigns a file's `path` from the `+++` line, so a headerless hunk is silently DROPPED (`files.filter(f => f.path)`), which then makes the citation-grounding gate drop every finding for that "file" (since `filesInDiff.has(finding.file)` is false). `diffFromPrFiles` (reviews/diff-loader.ts) prepends these headers itself when reconstructing from `pr_files.patch`, so the "Turn into eval case" freeze path is safe — but any test/script/UI that sets `input_diff` directly (the general `POST /agents/:id/eval-cases` route) must supply a FULL diff string with headers, not just the hunk body. Cost ~30 min of debugging 3 failing `evals.it.test.ts` assertions (precision/pass all silently null/false) before finding this.

[2026-07-13] pgvector query returns 0 rows after embedding model change. Root cause: pgvector columns have a FIXED dimensionality constraint at creation time. When the model changes (e.g., OpenAI 1536 → Anthropic 1024 → Deepseek 4096), existing embeddings and the column schema become mismatched. The new vectors are rejected silently by pgvector because they don't satisfy the column's `vector(old_dim)` constraint. Fix: write a data migration (NOT a schema migration per the no-new-tables rule) that re-computes embeddings with the new model before switching the model router. Pattern: `UPDATE embedding_table SET vec = NULL WHERE model_version != ?` (mark stale rows), then a backfill job calls `LLMProvider.embed()` in batches of 10 (pgvector is thread-safe but avoid >50 concurrent writes). Always run a sanity-check query after: `SELECT COUNT(*) FROM embedding_table WHERE vec IS NULL` should be 0. If you see "0 rows found" AFTER inserts + null-check is 0, the column's vectype() still doesn't match — check Postgres: `SELECT typname FROM pg_type WHERE oid = (SELECT atttypid FROM pg_attribute WHERE attname = 'vec' AND attrelid = 'embedding_table'::regclass)`. (embeddings/repository.ts pattern — also applies to any vector-backed search)
[2026-07-09] A freshly-added route (new `modules/<x>/routes.ts` + a `modules/index.ts` entry) 404s in the running app even though ALL tests pass — the `tsx watch src/server.ts` dev server did NOT reload on the new-file + static-import change, worsened by MULTIPLE competing watcher processes fighting over :3001 (a stale child keeps serving old code). Diagnose by the 404 BODY, not the status code: Fastify's default `{"message":"Route GET:/... not found",...}` = route not registered in the live process; our `AppError` `{"error":{"code":"not_found",...}}` = route exists, entity just missing. Compare against a known-good sibling route to classify. Fix is OPERATIONAL, not code: `pkill -f "tsx.*watch src/server.ts"`, confirm `ss -ltn | grep :3001` is free, then one fresh `cd server && pnpm dev`. Do NOT hunt for a code bug first.

[2026-07-06] `getResolvedCallers` (repo-intel/repository.ts) INNER JOINs `file_rank` on the caller's `from_path` — a caller whose file has NO `file_rank` row silently disappears from blast results. When seeding a persistent index for a test/demo, insert a `file_rank` row for EVERY caller `from_path`, not just the changed file, or "0 callers" despite present `references`.

[2026-07-06] Live review of seeded PR #482 returns 0 findings / score 100 despite a hardcoded `sk_live_` key: the seed (`db/seed.ts`, `pr_files` insert) only set `additions`/`deletions`, NOT `patch`. `loadDiff` (`reviews/diff-loader.ts`) then tries `git.diff(base, headSha)` — the seed's `headSha` (`a1b2c3d4e5f6`) is fake so no clone resolves it → falls back to `diffFromPrFiles`, which does `if (!f.patch) continue;` → EMPTY diff → the reviewer sees nothing → `grounding: "0/0 passed"`, `tokens_in` ~1.6k (system prompt only, no diff body). Fix: give each `pr_files` row a real unified-diff `patch` (the `@@` hunks ONLY — `diffFromPrFiles` prepends the `diff --git`/`---`/`+++` headers). Diagnostic tell: an empty-diff run has `tokens_in` ~1.6k vs a real diff's ~45k. The 2 findings the studio UI/`get_findings` still shows are a SEPARATE pre-seeded demo review (seed.ts:136, `model:'seed'`, `run_id` NULL), not run output.

[2026-07-06] `MockLLMProvider` (`adapters/mocks.ts`) had its `id`/constructor param narrowed to `'openai' | 'anthropic'` even though `LLMProvider.id` allows `'openrouter'`. Any feature whose `FEATURE_MODELS` default resolves to an openrouter model (e.g. `review_intent` now defaults to `deepseek/deepseek-v4-flash`) cannot be integration-tested until you widen `MockLLMProvider`'s `id` to include `'openrouter'`.

[2026-06-28] Drizzle `db.update().set(obj)` rejects a plain `{ status?: string }` when the column is typed as a text enum — TypeScript sees the types as incompatible. Fix: use conditional spreads the way `skills/repository.ts:90-96` does: `{ ...(fields.status !== undefined ? { status: fields.status } : {}) }`. The spread produces a type that satisfies the enum column type.

[2026-06-26] Adding a required field to a shared Zod schema breaks existing test fixtures that don't include it. Fix: use `.nullish()` (not `.nullable()`) for fields that are computed externally and not stored in DB — the type becomes `T | null | undefined`, which is backwards-compatible with old fixtures.
